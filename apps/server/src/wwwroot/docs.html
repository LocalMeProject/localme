معرفی و معماری پلتفرم لوکال‌می (LocalMe BaaS)

پلتفرم لوکال‌می یک زیرساخت جامع Backend-as-a-Service چندمستاجره (Multi-Tenant) بومی است که با هدف ارتقای سرعت توسعه اپلیکیشن‌های موبایل (Android, iOS) و وب‌اپلیکیشن‌ها پیاده‌سازی شده است. این سامانه توسعه‌دهنده را از زحمت کانفیگ سرور، مدیریت پایگاه داده، درگاه‌های پرداخت، احراز هویت پیامکی و سرورهای ذخیره‌سازی بی‌نیاز می‌سازد.

اصول کلیدی معماری لوکال‌می

  • ایزولاسیون بر پایه اسکیما (Schema-per-Project Isolation): هر پروژه دارای یک اسکیمای مجزا در پایگاه داده PostgreSQL 18 است. داده‌های مستاجران مختلف تحت هیچ شرایطی با یکدیگر تداخل نداشته و از بالاترین سطح امنیت و سرعت کوئری برخوردارند.
  • کلیدهای تفکیک‌شده به ازای هر سرویس (Per-Service Scoped Keys): برخلاف سیستم‌های قدیمی که از یک کلید عمومی سراسری استفاده می‌کردند، لوکال‌می برای هر سرویس یک کلید مستقل با ساختار lm_[service]_[project]_[id] صادر می‌کند. در صورت افشای کلید یک سرویس، سایر سرویس‌ها ایمن می‌مانند.
  • محاسبه مصرف دقیق و اعتباری (Pay-As-You-Go Ledger): مصرف منابع (تعداد کوئری‌ها، پیامک‌ها، حجم فایل‌ها و زمان پردازش توابع) با دقت میلی‌ثانیه‌ای و ریالی در یک دفترکل دوبل حسابداری ثبت و از کیف پول کسر می‌گردد.

چرخه کار توسعه‌دهنده

  1. عضویت و ورود با شماره همراه در سامانه.
  2. ایجاد یک پروژه جدید در کنسول توسعه‌دهندگان (هر توسعه‌دهنده در ابتدا با ۰ پروژه شروع می‌کند).
  3. ورود به صفحه اختصاصی هر سرویس در منوی کناری، تنظیم پارامترها و فعال‌سازی آن سرویس.
  4. کپی کردن کلید دسترسی اختصاصی همان سرویس و ارسال درخواست از اپلیکیشن کلاینت.

احراز هویت و ساختار کلیدهای دسترسی API

تمامی درخواست‌های ارسالی از سمت کلاینت‌ها (موبایل و وب) باید احراز هویت شوند. هدرهای استاندارد زیر برای برقراری ارتباط الزامی هستند:

نام هدر (Header) مقدار الزامی توضیحات
x-api-key lm_[service]_[proj]_[id] کلید اختصاصی سرویسی که قصد فراخوانی آن را دارید.
Authorization Bearer <JWT_TOKEN> توکن احراز هویت کاربر نهایی اپلیکیشن (برای دسترسی‌های کاربرمحور).
Content-Type application/json قالب ارسال داده‌ها در متدهای POST و PUT.

زیرساخت شبکه، دیتاسنتر و اتصال شاپرک

تمام سرورهای لوکال‌می در مراکز داده داخلی مستقر در منطقه تهران (ir-central-tehran) میزبانی می‌شوند.

  • IP خروجی ثابت و حاکمیتی (Egress NAT): 2.180.12.94 — تمامی ارتباطات با وب‌سرویس‌های شاپرک، سرشماره‌های پیامکی، و سازمان‌های دولتی از این آدرس IP ثابت انجام می‌پذیرد.
  • پایداری شبکه ملی اطلاعات: در شرایط اختلال اینترنت بین‌الملل، دسترسی کاربران داخلی به پلتفرم و اپلیکیشن شما به صورت ۱۰۰٪ پایدار و بدون وقفه برقرار می‌ماند.

سرویس پایگاه داده رابطه‌ای و PostgREST

این سرویس جداول دیتابیس پروژه را مستقیماً به صورت RESTful در اختیار کلاینت قرار می‌دهد. نیازی به نوشتن کنترلرهای اضافه در بک‌اند نیست.

اندپوینت‌های عملیاتی پایگاه داده

GET /_baas/v1/{projectId}/db/{tableName}

دریافت رکوردهای جدول به همراه قابلیت فیلترگذاری و صفحه‌بندی.

POST /_baas/v1/{projectId}/db/{tableName}

درج یک رکورد جدید در جدول مشخص‌شده.

PUT /_baas/v1/{projectId}/db/{tableName}/{id}

ویرایش و به‌روزرسانی مقادیر یک رکورد بر اساس شناسه.

DELETE /_baas/v1/{projectId}/db/{tableName}/{id}

حذف قطعی یک سطر از جدول.

فیلترها و عملگرهای جستجو (Query Operators)

gt / gte بزرگتر / بزرگتر مساوی ?price=gte.500000
lt / lte کوچکتر / کوچکتر مساوی ?stock=lt.10

سرویس ذخیره‌سازی ابری فایل (Object Storage)

سامانه نگهداری فایل‌های رسانه‌ای، تصاویر پروفایل، کاتالوگ محصولات و اسناد با تفکیک باکت‌های عمومی (Public) و محرمانه (Private).

آپلود فایل (Multipart Upload)

POST /_baas/v1/{projectId}/storage/{bucketName}/upload

هدرهای الزامی: x-api-key: lm_storage_... و ارسال فایل در فیلد file از نوع فرم چندبخشی.

دریافت یا دانلود فایل

GET /_baas/v1/{projectId}/storage/{bucketName}/{fileName}

توابع سرورلس لبه (Edge Functions)

اجرای کدهای جاوااسکریپت خالص در موتور ایزوله و پرسرعت Jint. ایده‌آل برای اعتبارسنجی کدملی، نرمال‌سازی شماره‌های تماس، هش‌گذاری، یا اتصال وب‌هوک به سرویس‌های ثالث.

فراخوانی و اجرای تابع

POST /_baas/v1/{projectId}/functions/{funcSlug}/exec

محیط اجرایی اسکریپت

// ورودی تابع در متغیر req قرار دارد
var body = req.body;

// اعتبارسنجی کدملی ایرانی (الگوریتم رسمی ثبت‌احوال)
function isValidNationalCode(code) {
  if (!code || code.length !== 10 || isNaN(code)) return false;
  var sum = 0;
  for (var i = 0; i < 9; i++) {
    sum += parseInt(code.charAt(i), 10) * (10 - i);
  }
  var rem = sum % 11;
  var last = parseInt(code.charAt(9), 10);
  return (rem < 2 && last === rem) || (rem >= 2 && last === (11 - rem));
}

var valid = isValidNationalCode(body.national_code);

// خروجی تابع در متغیر res بازگردانده می‌شود
res.json({
  is_valid: valid,
  national_code: body.national_code,
  verified_at: new Date().toISOString()
});

سیستم مالی، کیف پول و محاسبه مصرف (Billing & IPG)

لوکال‌می فاقد اشتراک ماهیانه اجباری است؛ هزینه خدمات صرفاً بر اساس مصرف واقعی از کیف پول اعتباری کسر می‌شود.

سرویس واحد سنجش نرخ مصوب (ریال) معادل تومان
پایگاه داده رابطه‌ای هر ۱,۰۰۰ کوئری REST ۱۰۰ ریال ۱۰ تومان
احراز هویت پیامکی هر پیامک ارسالی OTP ۸۰۰ ریال ۸۰ تومان

خطای اتمام موجودی (HTTP 402 Payment Required)

چنانچه موجودی کیف پول اعتباری به صفر برسد، درخواست‌های API با خطای 402 Payment Required مواجه خواهند شد. با افزایش اعتبار از طریق درگاه شاپرک، دسترسی بلافاصله احیا می‌گردد.

// LocalMe Client SDK for Web & Node.js
class LocalMeClient {
  constructor(projectId, keys) {
    this.projectId = projectId;
    this.keys = keys;
    this.baseUrl = 'https://api.localme.ir/_baas/v1';
  }

  // پایگاه داده
  async getRecords(table, queryParams = {}) {
    const qs = new URLSearchParams(queryParams).toString();
    const url = `${this.baseUrl}/${this.projectId}/db/${table}${qs ? '?' + qs : ''}`;
    const res = await fetch(url, {
      headers: { 'x-api-key': this.keys.database }
    });
    return await res.json();
  }

  // احراز هویت پیامکی
  async sendOtp(phone) {
    const url = `${this.baseUrl}/${this.projectId}/auth/otp/send`;
    const res = await fetch(url, {
      method: 'POST',
      headers: {
        'x-api-key': this.keys.auth,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({ phone })
    });
    return await res.json();
  }

  // اجرای تابع لبه
  async executeFunction(slug, payload) {
    const url = `${this.baseUrl}/${this.projectId}/functions/${slug}/exec`;
    const res = await fetch(url, {
      method: 'POST',
      headers: {
        'x-api-key': this.keys.functions,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(payload)
    });
    return await res.json();
  }
}

import requests

class LocalMeClient:
    def __init__(self, project_id: str, keys: dict):
        self.project_id = project_id
        self.keys = keys
        self.base_url = "https://api.localme.ir/_baas/v1"

    def get_records(self, table: str, params: dict = None) -> list:
        url = f"{self.base_url}/{self.project_id}/db/{table}"
        headers = {"x-api-key": self.keys.get("database")}
        response = requests.get(url, headers=headers, params=params)
        response.raise_for_status()
        return response.json()

    def send_otp(self, phone: str) -> dict:
        url = f"{self.base_url}/{self.project_id}/auth/otp/send"
        headers = {
            "x-api-key": self.keys.get("auth"),
            "Content-Type": "application/json"
        }
        response = requests.post(url, headers=headers, json={"phone": phone})
        response.raise_for_status()
        return response.json()

    def exec_function(self, slug: str, payload: dict) -> dict:
        url = f"{self.base_url}/{self.project_id}/functions/{slug}/exec"
        headers = {
            "x-api-key": self.keys.get("functions"),
            "Content-Type": "application/json"
        }
        response = requests.post(url, headers=headers, json=payload)
        response.raise_for_status()
        return response.json()

import 'dart:convert';
import 'package:http/http.dart' as http;

class LocalMeService {
  final String projectId;
  final Map keys;
  final String baseUrl = 'https://api.localme.ir/_baas/v1';

  LocalMeService({required this.projectId, required this.keys});

  // ۱. دریافت لیست رکوردهای جدول
  Future> getTableRecords(String table) async {
    final uri = Uri.parse('$baseUrl/$projectId/db/$table');
    final response = await http.get(uri, headers: {
      'x-api-key': keys['database'] ?? '',
    });

    if (response.statusCode == 200) {
      return jsonDecode(utf8.decode(response.bodyBytes)) as List;
    } else {
      throw Exception('خطا در دریافت اطلاعات: ${response.statusCode}');
    }
  }

  // ۲. ارسال پیامک OTP به شماره همراه کاربر
  Future sendOtp(String phoneNumber) async {
    final uri = Uri.parse('$baseUrl/$projectId/auth/otp/send');
    final response = await http.post(
      uri,
      headers: {
        'x-api-key': keys['auth'] ?? '',
        'Content-Type': 'application/json',
      },
      body: jsonEncode({'phone': phoneNumber}),
    );

    return response.statusCode == 200;
  }
}

کدهای وضعیت HTTP و راهنمای رفع اشکال

کد وضعیت عنوان خطا علت و راهکار رفع
200 OK عملیات موفق درخواست با موفقیت پردازش شد.
201 Created ایجاد موفق رکورد رکورد در جدول یا کاربر در سیستم با موفقیت ثبت شد.
400 Bad Request قالب داده نامعتبر بدنه JSON ارسالی معتبر نیست یا فیلدهای اجباری ارسال نشده‌اند.
401 Unauthorized کلید نامعتبر کلید هدر x-api-key ارسال نشده یا نامعتبر است.
402 Payment Required اتمام موجودی کیف پول اعتبار کیف پول پروژه تمام شده است. از پنل توسعه کیف پول را شارژ نمایید.
403 Forbidden عدم دسترسی به منبع سرویس مورد نظر برای پروژه غیرفعال شده یا سطح دسترسی ناکافی است.
404 Not Found منبع یافت نشد پروژه، جدول یا فایل مورد نظر در سامانه وجود ندارد.
429 Too Many Requests محدودیت نرخ فراخوانی تعداد درخواست‌ها در دقیقه از سقف تعیین‌شده فراتر رفته است.
